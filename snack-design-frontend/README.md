# snack-design-frontend · 食有数Bite微信小程序

基于用户交付的「食有数-定版交付」HTML 原型开发，原生 WXML / WXSS / JavaScript。当前已连接同级 `snack-design-backend` Java 后端，未提交草稿仍只存本机。

## 目录与导入

前端使用 `D:\wtt\小程序\snack-design-frontend`，后端使用 `D:\wtt\小程序\snack-design-backend`。

Windows 当前占用原 `snack-design` 目录，直接重命名两次失败。因此新前端目录是完整复制的可工作版本，原目录保留，未删除。请在微信开发者工具中重新导入新目录；确认正常后，关闭旧项目与占用旧路径的终端/会话，再自行归档或删除原目录。两个目录不是自动同步的，后续只维护新目录。

本轮保留了已有小程序 AppID，不需要重新填写测试 AppID。服务端正式微信登录仍需要独立配置 AppSecret，绝不能放到小程序中。

## 启动联调

### 1. 先启动免费AI和Java后端

默认改为云端OpenRouter免费模型，不在本机运行/下载大模型。需要注册免费API Key；免费检索由独立轻量SearXNG承担（不是大模型，不需要GPU）。配置见后端 `ZERO_COST_CLOUD.md`，可用 `start-zero-cost-cloud.cmd`。零价格模式下额度用完就停止，不启用付费搜索或模型fallback。

必须先在旧Java窗口按Ctrl+C释放8080，再从后端新目录启动。健康检查应包含 `apiVersion:3`，否则仍是旧运行版本。

仅需单独启动Java时：

```powershell
cd D:\wtt\小程序\snack-design-backend
mvn spring-boot:run
```

或双击后端的 `start-local.cmd`。保持窗口打开，浏览器访问 `http://127.0.0.1:8080/api/health`，应显示 `{"status":"ok"}`。

### 2. 再启动小程序

1. 微信开发者工具导入 `snack-design-frontend`。
2. 「详情 → 本地设置」勾选「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」，仅用于本地开发。
3. 点击编译，无需构建 npm。
4. 首页“试一包”直接离线查看预设demo；真实流程请用“手动输入配料表 → 确认上传 → 自动查询 → 查看记录”。

`utils/config.js`：

```javascript
module.exports = {
  baseUrl: 'http://127.0.0.1:8080/api',
  authMode: 'dev'
}
```

本地模式自动申请测试会话，不代表生产微信身份认证。关闭后端后，读取/保存会显示网络错误，不会静默回退本机记录，避免两套数据混用。

## 首页示例体验（不依赖后端）

首页“第一次用？先试一包”的燕麦脆饼卡片现在直接打开已经填充的示例配料表与分组解析，不再进入输入页。提供原味5项、可可味6项、坚果味6项三份预设虚构配方，页面顶部可切换。

示例无需登录、联网、Java后端或AI模型，不保存到用户记录、不改写草稿，也不冒充实时AI查询。来源标为演示参考，食用建议明确为预设演示。数据位于 `utils/demo.js`，与 `utils/records.js` 的真实接口流程隔离。

## 底部导航与扫码动作

底部使用 `custom-tab-bar/`，显示“首页 / 扫描 / 记录”。只有首页、记录是Tab页面；中间扫描是动作按钮，直接 `wx.scanCode`，不先切换到扫描介绍页。取消或拒绝权限后仍留在原Tab，快速重复点击不会启动多个扫码器。

扫码成功只展示读取内容，不自动打开二维码链接、不把条码当作配料或冒充商品查询。用户另行确认“输入配料”才进入编辑页。扫码工具位于 `utils/scanner.js`，首页的“扫描商品条码”入口也复用它。首页拍照入口仍可进入拍照说明页；该页面已改为普通页面，通过navigateTo打开。

更改TabBar配置后需完整编译；首次切换custom模式可清除编译缓存。扫码器需在微信开发者工具支持的环境或真机验证，本轮只有自动化替身测试，未操作真机摄像头。

## 数据链路

```text
页面 → utils/records.js → utils/api.js → wx.request
     → Java API → JDBC → 后端 data/snack.mv.db
```

- 上传：点击编辑页确认按钮后，配料文字提交服务端并保存。
- 不上传：照片、未提交的文字草稿。
- `utils/api.js`：请求超时、会话缓存、并发登录合并、401后只重登重试一次。
- `utils/records.js`：服务端记录增删改查、异步 AI 调研、进度和历史快照查询。
- `utils/storage.js`：草稿持久化，以及旧版本本机记录数据的兼容保留；页面不再从这里读取正式记录。
- 旧版本本机记录不会自动上传，不会被删除。旧草稿若引用原本机记录ID，无法更新为云记录，请复制原文后新建录入。
- 测试设备标识保存在本机；清空微信存储可能生成新的测试用户。正式微信登录使用服务端校验的 openid。

## 已有功能

首页、相机入口、原文核对、复合配料括号校验、草稿恢复、用户记录管理，以及 AI 联网调研。调研页显示用途、可能益处、风险、条件性用量、检索来源及摘录、核实状态、查询时间与历史快照。

## 上线 / 真机

本机 `127.0.0.1` 只适用于电脑上的开发者工具，手机上的该地址指手机本身。

正式接入需：

1. 后端使用 `prod` 配置，配置 `WECHAT_APP_ID` 和 `WECHAT_APP_SECRET`；生产配置中测试登录接口不存在。
2. 服务部署到 HTTPS 域名，微信后台配置 request 合法域名。
3. 前端 `baseUrl` 改为该域名下的 `/api`，`authMode` 改为 `wechat`。
4. 核对前后端使用相同 AppID；前端通过 `wx.login` 获得临时 code，再由 Java 调微信官方接口校验。
5. 完善隐私保护指引，做权限拒绝、断网、登录失效、重试、记录隔离和真机验收。

## AI 查询与结果页

默认云端入口为 `openrouter/free`，后端检查目录价格并把请求价格上限设为0；不下载本机模型、不使用计费搜索插件。需要免费账号API Key与免费检索组件，当前未完成真实云端推理验收，不能把模拟测试当作实际已运行。

上传原文后直接进入原设计的分组两列解析页，自动开始检索并显示真实结果，不再展示查询设置表单。食品类别移到原文编辑页选填；未填或原文引用未核实时不显示具体限量。返回已有结果不会自动重查，AI结论未经人工审核。

默认 `AI_ZERO_COST_ONLY=true` 会阻止收费云服务；免费额度或搜索不可用时如实失败。详见后端 `ZERO_COST_CLOUD.md`。免费并不意味着永久在线、无限次数或所有底层模型都开源，引用和建议边界仍见 `docs/AI_RESEARCH.md`。

## 能力边界

OCR、商品数据库未接入，相机照片仍需对照手动录入。新调研链路不限制配料名称，也不依赖旧示例知识表。引用来自官方域名不代表AI理解、标准现行性和适用性已核实；不做食品安全评级，不提供个人食用建议，不能以“无资料”判断安全。
