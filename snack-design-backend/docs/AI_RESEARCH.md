# 实时 AI 配料调研：配置、证据边界与验收

> 最新要求是云端且AI/搜索API调用费为0，默认已切换OpenRouter免费路由，具体配置以 [../ZERO_COST_CLOUD.md](../ZERO_COST_CLOUD.md) 为准。下方关于Ollama/OpenAI的配置属于历史方案；来源、用量和审核边界仍适用。不会自动回退收费服务。

## 当前默认免费接入与页面流程

默认模型已改为本机Ollama，联网资料检索由本机SearXNG承担，安装与启动说明见 [../FREE_AI.md](../FREE_AI.md)。免费指无按次API费用，不免除计算、网络与安装成本，也不能保证公开搜索引擎持续可用。Ollama/SearXNG当前尚未在本机安装，真实免费模型验收未完成。

原文确认后现在自动进入分组解析页，不再经过“联网查询设置页”。食品类别移到编辑页选填。以下OpenAI配置仅用于手动选择的云服务；两条路径共享证据校验与用量保护，不会自动回退收费服务。

## 当前实现的链路

```text
确认上传原文 → 保存用户记录 → 直接进入分组解析页并自动查询
→ Java 创建异步任务 → Ollama+SearXNG（默认）或显式配置的OpenAI检索
→ 结构化总结 → 检查检索出处 / 尝试核对网页原文摘录 / 过滤无法核对的用量
→ research_reports 保存独立快照 → 前端轮询展示 → 历史查询可回看
```

本流程没有配料名称白名单，苯甲酸钠或其他名称均由本次输入进入 AI 联网检索。旧 5 条示例知识不参与这条链路。旧 `/api/ingredients/analyze` 已返回 410；示例导入组件只在显式开启 `legacy-demo` 配置时启用，日常 local/prod 不导入。

**AI 查询日志入库不等于把 AI 内容升级为人工审核知识。** 快照包含配料名、用途、总结、可能益处、风险、条件性用量、引用、核对状态、模型和时间；不会自动覆盖人工知识表。今后若要把它作为可复用“权威知识库”，仍需审核、版本化和失效机制。

## 一、配置真实 AI 服务

当前这段描述的是可选OpenAI官方Responses API，不是默认免费路径，也不是任意 `/chat/completions` 服务。没有使用聊天助手本身的订阅或凭证，需要你自己的API密钥、可用额度及对应模型工具权限。

先停止旧的 Java 服务，在 PowerShell 中：

```powershell
cd D:\wtt\小程序\snack-design-backend
$env:AI_PROVIDER="openai"
$env:OPENAI_API_KEY="在你自己的终端填写API密钥"
$env:OPENAI_MODEL="gpt-4.1"
$env:AI_DAILY_LIMIT="30"
mvn spring-boot:run
```

密钥仅放在后端环境变量，不要粘贴到聊天、前端、Git 或截图里。PowerShell 环境变量只影响当前窗口及其子进程；在别的窗口双击启动脚本不会自动继承本窗口的新值。默认示例模型需以你账号的实际兼容性为准，不承诺所有账号都具备搜索工具权限。

当前请求发往 `https://api.openai.com/v1/responses`，`store=false`。不支持没有联网工具的聊天模型静默退化为“凭记忆回答”。无法联网、密钥错误、额度耗尽、模型不兼容、返回不完整时，都会保存/显示失败，而不是返回示例或伪造报告。

国内电脑若无法访问服务，需要使用符合服务商适用地区及相关要求的部署环境；本项目不通过不明代理传送密钥。

## 二、小程序如何使用

1. 使用 `snack-design-frontend` 项目，编译最新代码。
2. 手动输入，例如“苯甲酸钠”，点击确认上传原文。
3. 食品类别在原文编辑页选填，例如具体饮料类别；不要填写配料名称，不确定可留空。
4. 确认上传后直接进入分组解析页并自动查询，编辑页明确说明发送内容和AI使用。
5. 页面每3秒轮询进度，不保持数分钟的 HTTP 请求。离开页面任务仍继续，返回会恢复读取。
6. 前端显示用途、可能益处、风险、用量条件、资料链接、摘录、核实状态、查询时间和模型。
7. 查看保存记录不会自动重查。原文页明确提交会在没有匹配快照时自动查询；失败可重试。页面底部可回看最近10次历史快照。

## 三、怎样核对来源

允许检索的域名及其子域名：

- `nhc.gov.cn` 国家卫生健康委
- `samr.gov.cn` 国家市场监督管理总局
- `cfsa.net.cn` 国家食品安全风险评估中心
- `who.int` WHO
- `fda.gov` FDA
- `ecfr.gov` 美国法规
- `efsa.europa.eu` EFSA

响应必须包含成功执行的 `web_search_call`。总结中的来源网址必须同时满足：HTTPS、白名单域名、没有用户名信息、无非标准端口、确实出现在本次工具的 sources 或 URL 引用注解里。仅仅由 AI 自己在 JSON 里写出的网址不会被接受。某配料没有可追溯来源时，隐藏该配料的益处/风险结论，改成“资料不足”。

随后尝试读取官方 HTML，核对摘录是否逐字存在；每次报告最多做12次不同摘录的正文核对，正文大小上限1MB、8秒超时、不跟随重定向。可读取正文且包含摘录时标注“已在来源正文找到相同引用”；其他情况标注“正文引用尚未核实”。PDF、扫描件、非UTF-8、重定向、访问失败目前不会冒充正文核对通过。

**重要边界：**域名白名单和逐字摘录核对只能提高可追溯性，不能证明资料现行有效、AI总结语义正确、适用于这款商品，也不代表人工医学/法规审核。前端始终标注 AI 未审核。网页标题、未核实摘录和结论仍可能有错误，不能仅凭来源存在就认定科学结论成立。

## 四、用量保护

只有同时满足以下条件才显示 AI 提取的标准限量：

- 用户填写食品类别。
- AI 返回中国大陆地区、具体标准及版本、适用食品分类、数值和单位。
- 出处属于中国官方允许域名，且为本次真实检索的来源。
- 来源摘录与用量引用一致，并在读取的正文中找到相同引用。
- 摘录字面包含数值、单位和标准食品分类。

即便如此，页面仍标注“AI提取、标准现行性/类别映射待人工审核”，不当作法律合规判断或个人食用建议。无法满足条件则显示“未核实到具体限量”。外国标准、ADI、每日推荐摄入量与食品添加量不混用。

自然语言总结里出现明显的阿拉伯数字剂量表达会被隐藏，避免绕过用量区域的校验；这不是完整语义审查，不能替代人工审核。不要为了让页面显示一个数值而放松来源校验。

## 五、任务与存储

新增表 `research_reports`，按用户和原记录隔离，保存原文快照、食品类别、状态、模型、JSON结果、错误及时间。不会因为编辑了原文而把旧报告当成新结果；删除原配料记录时关联报告级联删除。

- 状态：queued / running / done / failed。
- 同一用户最多1个活动任务；全局2个工作线程、10个等待任务。
- 每用户24小时默认30次任务，可用 `AI_DAILY_LIMIT` 调整（失败任务也计数）。这不替代生产网关限流、全局费用上限和防滥用措施。
- 重启后未完成任务标记失败，用户可手动重查，不会因启动就自动再次扣费。
- 目前为单实例开发模型，未采用分布式任务队列；不能直接扩容多实例。

## 六、接口

均需要当前用户的 Bearer 会话：

| 方法 | 路径 | 返回 |
|---|---|---|
| POST | `/api/records/{id}/research` | body: `{"foodCategory":"饮料","refresh":true}`，创建异步查询 |
| GET | `/api/records/{id}/research/latest` | 当前原文最新报告，或 `{"exists":false}` |
| GET | `/api/research/{reportId}` | 轮询状态和报告 |
| GET | `/api/records/{id}/research/history` | 最近10次快照，可能对应修改前原文 |
