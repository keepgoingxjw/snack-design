# 最后食用建议

解析页顶部新增“最后建议”，配料条目可展示对应人群和建议；建议随AI调研快照保存，历史报告没有建议时保守显示“先核对，再决定”，不自动重新调用AI。

## 允许的建议

- `check_first`：先核对，再决定。
- `limit_frequency`：注意控制摄入与频率，不等于宣告整款食品有害。
- `avoid_for_group`：相关人群建议避免，必须说明具体限制人群，不能针对所有人。
- `consult_professional`：特殊情况先咨询专业人士。

AI返回action、audience、reason和sourceUrls。服务端生成展示标题及限制说明；非“先核对”的结论必须引用本次报告中正文摘录匹配成功的来源。缺少依据、声称所有人都应避免、给出“吃一点没事/绝对安全/整款能吃或不能吃”的理由时，降级为“先核对”。

整体建议从逐项建议中选择优先提醒的一项，同时指出其他资料不足的配料。它是需要优先关注的条件性提示，不是整款食品的安全评级，也不是把最严重潜在危害当作这款食品的实际风险。前端明确展示适用人群、相关配料、理由、证据及限制。

当前只有原文和选填食品类别，没有实际添加量、份量、是否过期变质、交叉接触、用户过敏/疾病/用药信息，所以不提供无条件“能吃”“不能吃”或“吃一点没事”的结论。即使原文引用匹配，也不证明AI理解和人群适用性正确，仍需审核。后续若要个体化建议，必须增加经过设计的健康/过敏偏好与实际标签信息，并建立专业审查流程。

代码：`AdvicePolicy.java`、`ResearchResultValidator.java`、`ResearchModels.java`；前端 `pages/result/`。旧记录兼容读取，失败/查询中不显示食用建议；不因查不到资料就建议所有人禁食。
